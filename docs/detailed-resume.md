# EvoHarnessAlert 详细简历项目描述

> 用于提供给导师、内推人或招聘方的详细版本。根据目标岗位可删减；其中“设计”内容只在确实完成方案论证时使用，已实现内容以代码和测试为准。

## EvoHarnessAlert 智能告警协同助手

**项目类型：** 个人项目（时间按实际填写）  
**技术栈：** Python、FastAPI、SQLAlchemy、MySQL、Redis、BM25、Chroma（可选）、pytest、Playwright、Docker Compose

### 项目概述

面向交易、支付、核销等服务链路的告警研判与交接场景，开发智能告警协同助手，将 Webhook/Prometheus 告警转换为统一事件，完成事件聚合、分级处置、知识检索、Agent 协作、异步通知与回放验证，帮助值班人员快速定位影响范围并保留完整处置轨迹。

### 业务接入与事件治理

- 基于 FastAPI 封装通用 Webhook 与 Prometheus Alertmanager 接入，将异构告警统一为包含来源、标签、指纹、优先级、类型、发生时间和恢复状态的数据对象。
- 建立 P0–P3 优先级与 PROBLEM、BUSINESS、EVENT、HOST 告警类型的双维度领域模型，通过别名映射和规则兜底处理外部系统字段差异。
- 基于来源、标题、告警类型和稳定标签生成告警指纹，排除实例、Pod 和时间戳等易变字段，降低实例滚动造成的重复告警。
- 按服务、告警类型和稳定指纹聚合 Incident，维护告警计数、最高优先级、确认状态和关闭状态，将原始告警转换为可跟进的处置对象。
- 按告警级别生成台账、事件更新和通知等工具计划：高优先级进入快速通知链路，中低优先级保留跟踪和审计记录。
- 实现告警确认、关闭、备注和交接记录接口，并在中文工作台中集中展示告警详情、证据、处置状态和操作历史。

### Agent、Harness 与安全控制

- 在 AlertAgentHarness 中统一处理输入脱敏、会话标识、Runtime 调用、短期记忆更新和执行轨迹持久化，降低 HTTP 接口层与业务逻辑的耦合。
- 使用 Task、Artifact、Message 和 Event 建模黑板协作状态，通过产物发布和事件追加组织上下文准备、候选回复和审查流程，保留可检查的中间结果。
- 为最终回复增加候选审查绑定与置信度门槛，只采纳与当前候选对应且通过审查的产物，并通过回归用例阻止旧审查结果误放行新候选。
- 为规则驱动的协作循环配置最大轮数和每轮认领数量，在预算耗尽时记录事件并返回兜底结果，限制无界执行。
- 将告警研判和排障回复指引拆分为可注册的 SKILL.md 资产，校验名称、工作流和安全说明，并以 READY/WARN/FAIL 状态暴露配置问题。
- 封装 Mock、Ollama 和 OpenAI-compatible 三类模型客户端，通过统一消息结构和配置入口切换推理服务，支持本地调试与外部模型接入。

### Memory、RAG 与工具执行

- 基于 Redis List 实现按用户和会话隔离的短期记忆，支持消息追加、窗口裁剪和 TTL 刷新；默认保留最近 40 条消息并设置 24 小时过期。
- 将较长对话压缩为有界确定性摘要，同时保留最近八条脱敏原文，在控制上下文长度的同时保留本轮排障细节。
- 围绕 Runbook、SOP 和服务说明实现文档入库，支持文本/PDF 读取、重叠切片、来源记录和可检索单元持久化。
- 在 KnowledgeService 中组合 BM25 关键词召回与可选 Chroma 向量召回，对候选结果进行融合和本地规则重排，兼顾错误码精确匹配与语义检索。
- 为向量检索提供异常处理、关键词检索降级、索引重建和快照入口，使检索组件可替换并保留运维排障路径。
- 使用 MySQL ToolJob 保存工具类型、执行状态、尝试次数和计划执行时间，配合轮询工作线程处理台账、事件更新和通知任务。
- 实现 log 与 SMTP 通知模式，覆盖配置缺失、发送失败、成功记录和重复结果复用分支，降低常规重试造成的重复通知。
- 为工具任务实现延迟重试、次数耗尽转死信和启动恢复未完成任务，并保留失败原因及审计记录，支持异常任务复盘。

### 测试、回放与交付

- 根据告警规格整理 20 类故障场景，为每类构造五种异常处理变体，生成 100 条中文合成回放样本，覆盖四级优先级和四类告警入口。
- 为回放样本冻结告警输入、权限范围、工具请求/响应、证据引用、预期任务计划和禁止动作，校验事实只引用成功取证结果。
- 使用确定性脚本生成版本化数据，测试样本编号唯一性、场景数量和优先级分布，降低手工维护导致的样例与代码不一致。
- 使用 Mock、Redis 内存替身和外部服务隔离验证限流、通知失败、短期记忆裁剪及缓存不可用降级，保持核心单测可离线执行。
- 通过边界测试覆盖时间时区转换、Redis 最近消息读取限制、非对象缓存数据、队列重试、Skill 校验和候选采纳等问题，并将缺陷复现场景纳入回归。
- 编写 Playwright 脚本验证筛选、故障变体切换、备注、下载、模拟接入、认证失败和响应式布局，保留桌面与移动端截图用于交互回归。
- 采用文件白名单生成源码交付包，排除本地凭据、缓存、运行台账和克隆仓库，生成 SHA-256 清单并回读校验，附部署说明与规格实现对照表。

### 可作为“项目成果”的表达

- 形成从告警接入、事件聚合、Agent 协作、知识检索、工具执行到通知审计的完整演示链路。
- 建立可重复回放的数据契约和测试替身，使核心规则、失败分支和安全边界能够在无企业依赖的环境下复现。
- 沉淀中文告警工作台、技能资产、回放数据集、测试报告和部署说明，便于后续按岗位方向继续扩展。
