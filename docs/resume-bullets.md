# EvoHarnessAlert 简历素材：背景、技术栈与 50 条亮点

## 一、项目背景

**项目名称：EvoHarnessAlert 智能告警协同助手**

生产环境的告警规则由运维/SRE 预先配置；当下单、支付、核销等链路触发告警后，值班人员仍需跨日志、监控、调用链、代码和排障文档完成研判。本项目围绕告警触发后的处置流程，建设告警标准化、事件聚合、多 Agent 协作、知识检索、异步通知和可追溯报告能力，并通过中文工作台与可重复回放样本支持开发验证。

简历短版：

> 面向团购交易链路的告警研判场景，开发基于 FastAPI、MySQL、Redis 的多 Agent 告警助手，支持 P0–P3 告警接入、事件聚合、知识检索及异步处置任务，通过执行轨迹和回归测试提高排查过程的可追溯性。

项目定位写“个人项目 / 团队项目 / 企业实践”中的真实一种。示例业务不等于在某企业真实上线，不把参与阅读或调用接口写成主导研发。

## 四、50 条可选亮点

下列编号对应上表。01–40 依据当前代码或本次交付组织，使用者应只选自己实际完成且能解释的内容；41–50 为文档中的生产设计方案。能力描述不自动等于性能提升，不附未经测量的百分比。

### A. 告警接入与 Agent 协作（01–10）

1. **统一告警接入：** 基于 FastAPI 封装通用 Webhook 与 Prometheus Alertmanager 接入，将异构告警转换为统一数据对象，保留标签、指纹、发生时间和恢复状态，支持后续聚合与追溯。
2. **领域建模：** 将告警优先级与业务类型解耦，建立 P0/P1/P2/P3 和 PROBLEM/BUSINESS/EVENT/HOST 两个维度，通过别名映射及规则兜底统一外部输入。
3. **稳定告警指纹：** 基于来源、标题、告警类型和稳定标签生成去重指纹，排除实例、Pod 和时间戳等易变字段，减少实例滚动变化造成的重复事件。
4. **事件聚合：** 按服务、类型和告警指纹聚合 Incident，维护告警计数、最高优先级及确认/关闭信息，将原始告警转换为可跟进的处置对象。
5. **分级处置策略：** 按 P0–P3 生成工具计划，高优先级关联通知、中优先级跟踪事件、低优先级记录台账，使通知和留痕规则可独立测试。
6. **对话编排封装：** 在 AlertAgentHarness 中集中处理输入脱敏、会话标识、Runtime 调用、短期记忆更新和执行轨迹持久化，降低 HTTP 层与业务逻辑的耦合。
7. **黑板协作原型：** 使用 Task、Artifact、Message 和 Event 建模 Agent 协作状态，通过产物发布与事件追加组织上下文准备、候选回复及审查流程，保留各阶段可检查的中间结果。
8. **候选采纳门槛：** 为最终回复增加安全审查关联和置信度门槛，仅采纳已通过当前候选审查的产物，并通过回归测试阻止旧审查结果误放行新候选。
9. **运行预算控制：** 为规则驱动的协作循环配置最大轮数和每轮认领数量，在预算耗尽时记录对应事件并返回兜底结果，限制无界执行。
10. **可维护技能资产：** 将告警研判与排障回复指引独立为 SKILL.md，通过注册表扫描并校验名称、工作流和安全说明，以 READY/WARN/FAIL 状态暴露配置问题。

### B. Memory、RAG 与模型接入（11–18）

11. **短期记忆窗口：** 基于 Redis List 实现会话消息追加、窗口裁剪与 TTL 刷新，按用户及会话区分存储键，默认保留最近 40 条消息并设置 24 小时过期。
12. **上下文压缩：** 将较长对话压缩为有界的确定性摘要并保留最近八条脱敏原文，兼顾历史背景与本轮细节，避免模型输入随会话长度持续累积。
13. **知识入库：** 围绕运维 Runbook、SOP 和服务说明构建文档入库服务，支持文本/PDF 读取与重叠切片，将知识内容及来源保存为可检索单元。
14. **混合检索实现：** 在 KnowledgeService 中组合 BM25 关键词召回与可选 Chroma 向量召回，对候选进行融合和本地规则重排，兼顾错误码精确匹配与语义检索需求。
15. **检索降级与索引维护：** 为向量检索提供异常处理、关键词检索降级及索引重建/快照入口，使检索组件可替换并保留运维排障入口。
16. **检索指标验证：** 编写 Recall@K、Precision@K 与 NDCG 的计算测试，使用固定排名和独立手算结果校验公式，覆盖未命中、重复来源及空评测集等边界。
17. **模型客户端适配：** 封装 Mock、Ollama 与 OpenAI-compatible 三类模型接入方式，通过统一消息结构和配置入口切换推理服务，方便本地调试和外部模型接入。
18. **Agent 模型配置：** 建立按 Agent 角色读取模型参数的注册表，支持全局默认配置和角色级覆盖，并测试未配置时的回退行为。

### C. 异步工具与审计（19–24）

19. **持久化工具队列：** 使用 MySQL ToolJob 保存工具类型、执行状态、尝试次数和计划执行时间，配合轮询工作线程处理台账、事件更新和通知任务。
20. **任务线程池隔离：** 为通知与台账任务分配独立线程池，按工具类型分发执行，降低两类任务争用同一执行资源的影响。
21. **通知投递：** 实现 log 与 SMTP 通知模式，覆盖配置缺失、发送失败和成功记录分支，并依据成功记录复用结果，减少常规重试造成的重复通知。
22. **工具治理与审计：** 建立工具策略注册表及审计服务，按工具名称和告警优先级判断准入并记录决策，支持对未知工具和不允许的通知请求进行拦截验证。
23. **失败恢复：** 为工具任务实现延迟重试、次数耗尽转死信和启动时恢复未完成任务，并用会话替身验证状态转换及失败原因留存。
24. **审计模型：** 使用 SQLAlchemy 建立告警、事件、通知、台账、任务与 Agent 轨迹实体，将输入、处置动作及工具结果关联，支持后台查询与问题复盘。

### D. 前端工作台与交互（25–30）

25. **中文值班工作台：** 使用原生 JavaScript 和响应式 HTML/CSS 构建告警控制台，提供服务搜索、P0–P3 优先级筛选和四类型筛选，集中展示告警列表与详情。
26. **告警接入交互：** 实现告警原文粘贴、优先级/类型选择及服务标注表单，通过现有 Webhook API 接入后端，并展示请求失败和提交状态。
27. **证据与回放展示：** 关联展示样本 Evidence ID、工具返回、预期协作路径和报告，支持正常、超时、冲突、权限拒绝、待审批五种变体切换，便于核对异常分支。
28. **处置记录交互：** 接入 Incident 确认、关闭和备注接口，将研判与交接记录集中到详情页；同时提供独立模拟状态用于本地演练。
29. **动态内容安全渲染：** 对告警标题、描述、证据和备注进行 HTML 转义，补充恶意标签输入回归用例，避免动态展示把输入文本解释为可执行页面内容。
30. **演示与真实数据分离：** 在前端区分模拟回放和同源后端连接，明确标识合成数据与预期结论，并支持导出单条案例及完整数据集，方便复现和交付。

### E. 数据、测试与交付（31–40）

31. **场景化测试数据：** 根据告警规格整理 20 类故障场景，为每类构造五种异常处理变体，形成 100 条中文合成回放样本，覆盖 P0–P3 与四类告警入口。
32. **冻结回放契约：** 为样本定义告警输入、权限范围、工具请求/响应、证据引用、预期任务计划和禁止动作，校验事实仅引用成功取证结果，支持可重复的契约回归。
33. **数据生成一致性：** 使用确定性脚本生成版本化回放数据，测试样本编号唯一性、场景数量及优先级分布，降低手工维护导致的样例与代码不一致。
34. **规则路由回归：** 使用 100 条回放输入执行当前 Runtime 的规则路由，逐例校验意图、优先级和类型，不将尚未实现的工具执行或审批能力混入路由通过率。
35. **外部依赖替身：** 使用 Mock 和 Redis 内存替身隔离数据库、缓存及邮件依赖，验证限流、通知失败、短期记忆裁剪和缓存不可用降级，保持单测可离线执行。
36. **缺陷驱动回归：** 通过边界测试发现并修复告警时间时区转换、Redis 最近消息读取限制及非对象缓存数据异常三个问题，将复现场景纳入持续回归。
37. **功能点测试建设：** 围绕告警规则、队列重试、Skill 校验、最终采纳和检索指标补充 92 个参数化测试场景，使该阶段测试结果从 22 项通过增加到 114 项通过，另 3 项 MySQL 集成测试因缺少测试库跳过。
38. **安全边界样例：** 在合成回放集中加入跨租户拒绝、证据矛盾和写操作待审批案例，并校验拒绝响应无证据正文、失败快照不进入事实引用，明确后续端到端验收条件。
39. **前端自动化验证：** 编写 Playwright 检查脚本，覆盖筛选、故障变体切换、备注、下载、模拟接入、认证失败及响应式布局，保留桌面和移动端截图用于交互回归。
40. **源码交付工程：** 采用文件白名单生成 ZIP/TAR 源码包，排除本地凭据、缓存、运行台账和克隆仓库，生成 SHA-256 清单并回读校验，附部署说明及规格实现对照表。

### F. 生产架构方案（41–50，保留“设计”措辞）

41. **执行边界设计：** 设计 Agent Loop、Harness 与 Runtime 的分层合同，分别承接动作提议、流程/权限控制和受限执行，通过 Action/Observation 连接，避免推理直接修改业务状态。
42. **优先调度设计：** 设计四级 Redis ZSET 就绪队列，按 P0–P3 派发并保持同级 FIFO，配合预留槽位控制低优先级任务对紧急告警的资源占用。
43. **租约与恢复设计：** 设计原子 Claim、租约续期和 MySQL Checkpoint，在任务领取、工具完成及产物发布边界记录状态，为 Worker 异常后的恢复和重复执行控制提供依据。
44. **权限隔离设计：** 设计结合 RBAC 与 ABAC 的租户、服务、环境和时间窗校验，将权限过滤前置到工具调用与知识检索，限制跨组排查的数据可见范围。
45. **证据成果设计：** 设计包含事实、假设、Evidence ID、缺口、版本和下游建议的 Artifact Schema，要求已确认结论具备可核验证据，并保留冲突版本以支持复盘。
46. **上下文预算设计：** 按告警级别分配 Incident 总预算及单次模型调用配额，设计日志聚类、代码片段筛选和成果摘要规则，保留证据引用与冲突信息。
47. **企业检索方案：** 设计 MySQL 知识元数据、Elasticsearch BM25/向量双路召回及 RRF 融合链路，规划权限前过滤、版本生效约束与重排降级策略。
48. **领域重排训练方案：** 设计以告警 Query、正例切片和难负例构成的重排训练集，规划 Qwen Reranker LoRA 训练、独立评测和版本回退流程，避免训练/评测样本泄漏。
49. **只读代码取证方案：** 设计按异常栈、变更号或 API 符号触发的代码分析流程，通过仓库授权、版本冻结、文件/行数预算和受限沙箱缩小取证范围，输出可定位的代码引用。
50. **Skill 演进方案：** 设计复盘反馈驱动的 Skill 候选生成、离线回放、Owner 审核、影子运行和灰度回滚流程，使 Prompt/流程更新以版本化资产受控发布。

## 五、组合成一段简历的示例

**EvoHarnessAlert 智能告警协同助手｜个人项目｜时间按实际填写**

**项目背景：** 面向团购交易链路的告警研判与交接场景，将已触发的运维告警转化为可跟进事件，提供多 Agent 协作、知识检索、异步通知和执行轨迹能力。

**技术栈：** Python、FastAPI、SQLAlchemy、MySQL、Redis、BM25、pytest、Docker Compose。

- 基于 FastAPI 接入 Webhook 与 Prometheus Alertmanager，统一告警优先级、类型、标签及恢复状态，支持后续事件聚合。
- 基于服务、类型和稳定指纹聚合 Incident，维护最高优先级与处置状态，按级别生成台账、事件和通知工具计划。
- 使用 Task/Artifact/Event 建模黑板协作，增加当前候选审查绑定、置信度门槛和运行轮数限制，保留可追溯的中间产物。
- 基于 Redis List 实现短期记忆窗口与 TTL，采用有界摘要加最近消息组织上下文，并对写入和读取内容执行脱敏。
- 为告警规则、任务队列与记忆边界编写回归测试，修复时区转换和缓存读取问题；通过测试替身隔离外部服务依赖。

以上是五条的完整结构示例。RAG 岗位可将“事件聚合”或“Redis 记忆”替换为 14、16；后端岗位可用 19、23 替换黑板协作；不要一次加入全部技术。
